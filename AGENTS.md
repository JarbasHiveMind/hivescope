# AGENTS.md — `hivescope`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

Hivescope is an in-process E2E test harness for the HiveMind protocol. It builds
`MasterNode` / `SatelliteNode` / `RelayNode` topologies wired together directly in
memory, with no real sockets, servers, or network processes — `InProcessHiveShim`
stands in for `HiveMessageBusClient` and `LoopbackNetworkProtocol` stands in for the
websocket transport. It exists to let hivemind-core and downstream repos assert
message-routing behavior across the wire protocol quickly and deterministically.
Part of the [HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core), whose
`ClientDatabase`/`HiveMindListenerProtocol` interfaces this harness's shims mirror.
Consumed by hivemind-core's own e2e suite and by
[hivemind-test-harness](https://github.com/JarbasHiveMind/hivemind-test-harness) for
multi-repo topology and stress scenarios.

## Layout / build / test

- Package module: `hivescope/`. Tests live in `tests/` (check before adding — do
  not create a second test directory). Copy-paste protocol templates live in
  `templates/`, one per `HiveMessageType`, tracked against the coverage table in
  `LIBRARY.md`.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[plot]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`. Tests marked
  `slow` may take longer; tests decorated `xfail(strict=False)` are pending
  protocol coverage (currently RENDEZVOUS, blocked on
  [ws#103](https://github.com/JarbasHiveMind/hivemind-websocket-client/pull/103)) —
  do not "fix" these by relaxing the assertion, only by removing the marker once
  hivemind-core actually grows the handler.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. `pyproject.toml` already documents
  two such floors: the `hivemind-core`/`ovos-bus-client` 2.x-line floor (avoids a
  stable-release resolution trap for consumers) and the `cryptography<42` cap
  (works around a released `hivemind-websocket-protocol` wheel's stale pyOpenSSL
  pin). Do not remove either without re-verifying the underlying releases.
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`).
- Everything in `pyproject.toml` (deps, metadata, version). Never install from
  git — depend on a published PyPI alpha. (The README's `git+https://...@dev`
  install snippets are for tracking unreleased `dev` during active development
  only, not the steady-state consumer pattern.)
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This harness is a **routing-conformance** tool: it proves that HiveMessages of
  each type reach the right node with the right ACL outcome. It does not exercise
  real transport (no sockets), and it does not exercise cryptographic correctness
  of the Noise/RSA handshake beyond the pass/fail signal the real handshake code
  already returns — `InProcessHiveShim` calls the real
  `HiveMindSlaveProtocol`/`HiveMindListenerProtocol` handshake code in-process, it
  does not reimplement or bypass it. Do not add transport-layer (raw socket,
  TLS) or crypto-internals coverage here; that belongs in
  hivemind-websocket-protocol / poorman_handshake.
- `InProcessHiveShim`, `InMemoryClientDatabase`, and `LoopbackNetworkProtocol`
  are stand-ins for real hivemind-core objects and must stay in lockstep with
  whatever hivemind-core actually reads off them. `NodeIdentity`/`Client` fields
  such as `.password` (added to hivemind-core's client model at
  `hivemind-core>=0.7.1a1`) exist on these shims for that reason — when
  hivemind-core's `ClientDatabase`/`HiveMindListenerProtocol`/`NodeIdentity`
  surface adds or renames a field, mirror it here in the same PR, and note the
  originating hivemind-core version in a comment the way `.password` does.
  Downstream repos floor their `hivescope` dependency on the version that added
  the shim fix they need — a shim/reality mismatch here fails silently as a
  false-green test elsewhere.
- `InMemoryClientDatabase` is intentionally not a full plugin: it takes a lock
  only around dict/id-counter mutation and returns `Client` objects unsynchronized
  (see the comment in `hivescope/database.py`). Do not "fix" this into a stricter
  lock without checking it doesn't reintroduce contention on the loopback event
  loop thread.
- ACL/policy assertions must check the actual denial signal (e.g. a
  `hive.policy.denied` response), never just that the recorder logged an inbound
  message — the recorder logs before policy runs, so it cannot prove a message
  was denied.
- Keep the protocol-matrix coverage table in `LIBRARY.md` and the `templates/`
  directory in sync: every `HiveMessageType` needs an assertion helper, a
  template, and a coverage-table row: **ready** once hivemind-core actually
  routes it, **pending** (`xfail(strict=False)`) otherwise, with the tracking
  issue/PR linked.
